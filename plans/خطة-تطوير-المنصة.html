الركائز الثلاث الناقصة

1عزل المؤسسات

المنصة أحادية المستأجر بالكامل — لا يوجد مفهوم «مؤسسة/مستشفى» في قاعدة البيانات. العزل بالكود على مستوى القسم فقط.

2الامتثال الصحي

لا تشفير للبيانات الحساسة، ولا سجل تدقيق محكم، ولا سياسات احتفاظ — متطلبات إلزامية للمستشفيات.

3الطبقة التجارية

لا صفحة تسويقية، ولا تسجيل ذاتي، ولا اشتراكات/فوترة، ولا إدارة حسابات مؤسسية.

02 · الأساس القائم

نقاط القوة — نبني عليها ولا نلمسها

تقييم مباشر للكود (لا اعتماد على تقارير سابقة) كشف أساساً هندسياً متيناً يستحق البناء عليه بدل إعادة الكتابة:

المجالالتقييم
المعماريةNestJS modular نظيف، فصل واضح للمسؤوليات، Prisma بفهرسة مدروسة حسب أنماط الاستعلام الفعلية
دورة حياة التذكرةآلة حالات (State Machine) موثّقة تفرض تأكيد المُنشئ قبل الإغلاق — من أفضل ما في الكود
الأمان المحيطيJWT fail-fast · bcrypt cost 12 · قفل الحساب (5 محاولات/15 دقيقة) · Helmet + CSP + HSTS · CORS allowlist · CSRF · Throttler بـ6 طبقات
رفع الملفاتفحص الامتداد + MIME + magic-byte + منع path-traversal + حد 5MB (دفاع متعدد الطبقات)
Real-timeSocket.IO مع Redis adapter · إدارة اتصال صحيحة · rate limiting لكل حدث
RBACثلاث طبقات: دور المستخدم ← صلاحيات القسم ← تجاوزات لكل مستخدم (13 صلاحية دقيقة)
الواجهة (UI)تصميم متماسك · Dark mode · ثنائي اللغة AR/EN + RTL · responsive · React Query
التوثيقتوثيق ضخم: 54 endpoint · ER diagram · أدلة لكل دور · تقارير تدقيق
حقيقة مُتحقَّق منها: الباك-إند يُبنى بنجاح (اختبار مباشر — exit 0)، وحِزم zod وcsrf-csrf موجودة. ادّعاء «الـ build مكسور» في أحد التقارير السابقة غير صحيح — وهذا يؤكد أهمية التحقق المباشر قبل أي قرار.

الخلاصة

النظام مبنيّ جيداً في جوهره؛ ما يفصله عن الاحترافية التجارية ليس عيوباً معمارية بل إضافات وميزات ناقصة — وهذا يجعل الاستثمار في التطوير أعلى عائداً بكثير من إعادة البناء من الصفر.

الفجوات الحرجة — المعمارية والامتثال

معمارية بنية النظام

أحادي المستأجر بالكامل

لا يوجد كيان Organization/Tenant. العزل بالكود على مستوى القسم فقط — أخطر عائق أمام تسويق المنصة لعدة مستشفيات.

لا Row-Level Security

لا حماية على مستوى قاعدة البيانات ضد تسرّب البيانات بين المؤسسات — دفاع واحد فقط بدل طبقات.

توجيه الواجهة يدوي

App.tsx يستخدم useState بدل react-router (مثبّت وغير مُستخدم) — لا روابط عميقة ولا حماية مسارات حقيقية.

خدمة ضخمة (God Service)

tickets.service.ts يتجاوز 1000 سطر — دَين تقني يصعّب الصيانة والتوسّع.

امتثال الجاهزية الصحية (Healthcare / HIPAA)

لا تشفير للبيانات الحساسة

الأسماء والهواتف والملاحظات (PHI/PII) مخزّنة نصاً صريحاً — غير مقبول لبيانات المرضى.

سجل تدقيق غير محكم

أعمدة ipAddress/userAgent موجودة لكن لا تُملأ أبداً؛ الكتابة يدوية متناثرة وغير tamper-evident.

تخزين ملفات محلي غير مشفّر

لا S3/object storage، لا فحص فيروسات، لا تشفير — مشكلة كبيرة لبيانات المرضى وقابلية التوسّع.

لا احتفاظ ولا نسخ احتياطي

لا سياسات retention/erasure، لا نسخ احتياطي أو DR في الريبو — متطلبات امتثال أساسية.

الأثر: هاتان المجموعتان تمثّلان بوّابة الدخول للقطاع الصحي — لا يمكن التعاقد مع مستشفى دون عزل مؤسسات موثوق وضوابط حماية بيانات المرضى.

03 · ما الذي ينقص

الفجوات الحرجة — الأمان والمنتج والجودة

أمان أولوية فورية

الخروج لا يُبطل التوكن

refresh token صالح 7 أيام حتى بعد الخروج — لا blacklist ولا rotation. نافذة خطر عند سرقة التوكن.

تحقّق مدخلات ناقص

التحقق (Zod) على endpoint واحد من ~54؛ الباقي body: any — سطح هجوم واسع.

تسريب صلاحيات بالتحليلات

getDepartmentPerformance() يتجاهل معاملاته فالمشرف يرى كل الأقسام.

لا إدارة ذاتية لكلمة المرور

لا endpoint لتغيير/استرجاع كلمة المرور رغم وجود flag forcePasswordChange.

منتج الطبقة التجارية

  • لا صفحة هبوط/تسويق ولا تسجيل ذاتي ولا onboarding
  • لا اشتراكات/فوترة/خطط ولا إدارة حساب مؤسسي
  • لا بريد إلكتروني/SMS (إشعارات push فقط) — ضروري للتنبيهات والاسترجاع

جودة الدَّين التقني

  • صفر اختبارات فعلية رغم تهيئة Vitest كاملة
  • any منتشر (~146 backend / ~107 frontend) + strict:false
  • لا CI/CD ولا ESLint/Prettier ولا logging مُهيكل ولا metrics/APM
تنبيه أمني مُصلَح بالفعل: كانت هناك أسرار مكتوبة داخل docker-compose.yml (كلمة مرور DB + أسرار JWT). تمّ إخراجها إلى .env وإنشاء .env.example كجزء من الإصلاحات الفورية (المرحلة 0).
