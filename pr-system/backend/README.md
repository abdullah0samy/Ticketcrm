# ABC Hospital — PR Service (standalone)

نظام **علاقات ورضا المرضى (Patient Relations)** بعد فصله من مونوليث `ABCHospital`
ليصبح خدمة مستقلة بمسارها ومنفذها الخاص.

---

## لماذا كان الفصل ممكناً

تطبيق `pr` كان معزولاً بالفعل داخل المونوليث:

| الفحص | النتيجة |
|-------|---------|
| مفاتيح أجنبية إلى `users` أو `ticket` | **صفر** |
| `dependencies` في أول ترحيل | **`[]`** (فارغة) |
| استيرادات خارجية | 3 فقط: `PhoneNumber`، `validate_phone`، وenum‑ين |

لذلك تُنقل جداول `pr_*` دون أي جراحة على المفاتيح.

## البنية

```
pr-service/
├── manage.py
├── requirements.txt
├── prcore/              ← إعدادات المشروع (بديل ABCHospital)
│   ├── settings.py      ← كل الأسرار من متغيرات البيئة (لا شيء مكتوب في الكود)
│   ├── urls.py          ← يثبّت الخدمة على /api/pr/ (نفس المسار العام السابق)
│   ├── helpers.py       ← PhoneNumber + WhatsAppHandler (منسوخة ومقلّمة)
│   ├── validators.py    ← validate_phone
│   ├── paginators.py
│   └── exceptions.py
├── pr/                  ← التطبيق كما هو (23 ترحيلاً محفوظة)
└── users/               ← للمصادقة فقط (نفس جداول المونوليث)
```

### لماذا `users` موجود؟

الصلاحيات في `pr` تقرأ `request.user.get_role` و`request.user.department.modules`.
نسخة `users` هنا **لا تعرّف واجهات API** — فقط النماذج، وهي تشير إلى **نفس الجداول**
(`users_userinfo`, `users_department`)، فتظل توكنات DRF الحالية تعمل بلا أي تغيير.

هذه **المرحلة الأولى** من الفصل (قاعدة بيانات مشتركة). الفصل الكامل للبيانات خطوة لاحقة.

### متغيرات البيئة

| المتغير | الافتراضي | ملاحظة |
|---------|-----------|--------|
| `PR_SECRET_KEY` | مفتاح تطوير | **إلزامي في الإنتاج** |
| `PR_DEBUG` | `true` | اجعله `false` في الإنتاج |
| `PR_ALLOWED_HOSTS` | `*` | حدّده في الإنتاج |
| `PR_DB_NAME/USER/PASSWORD/HOST/PORT` | `abc` / `postgres` / `postgres` / `127.0.0.1` / `5445` | |
| `PR_CORS_ORIGINS` | — | قائمة بيضاء مفصولة بفواصل |
| `PR_WHATSAPP_API_URL` | فارغ | فارغ ⇒ الإرسال معطّل |

## فروق مقصودة عن المونوليث

| # | الفرق | السبب |
|---|-------|-------|
| 1 | **لا أسرار في الكود** | المونوليث يضمّن `SECRET_KEY` وكلمة مرور القاعدة ومفاتيح طرف ثالث |
| 2 | **`verify=True` على طلبات WhatsApp** | المونوليث كان يعطّل التحقق من TLS (`verify=False`) |
| 3 | **Swagger محمي خارج وضع التطوير** | كان مكشوفاً للعامة بلا مصادقة |
| 4 | **`AnonRateThrottle` = 60/دقيقة** | كان `10000000/day` أي بلا حد فعلي |
| 5 | **صلاحية قراءة الاستبيانات مُصلَحة** | كان الشرط مقلوباً فيسمح لأي مستخدم غير أدمن بقراءة بيانات المرضى |

> الفرق رقم 5 ثغرة **PHI** حقيقية مُثبتة بالتجربة — راجع `plans/خطة-التطوير-الموحدة.md`.

## الواجهة (UI)

واجهة PR موجودة داخل تطبيق البرودكشن (`ticket-front-current`) تحت المسار `/pr`:

| المسار | الشاشة |
|--------|--------|
| `/pr` | الصفحة الرئيسية |
| `/pr/create` | إنشاء استبيان جديد |
| `/pr/view` | قائمة الاستبيانات |
| `/pr/view/:id` | تفاصيل استبيان |
| `/pr/statistics` | إحصائيات PR |

وهي **موصولة بهذه الخدمة** عبر عميل axios مستقل (`prApi` في `src/api/axios-global.js`)
يُضبط بمتغيّر البيئة:

```
REACT_APP_PR_API_BASE=http://localhost:8001/api
```

إن لم يُضبط المتغيّر يعود العميل للمونوليث تلقائياً، فلا تنكسر أي بيئة لم يُطبَّق
عليها الفصل بعد.

> استثناء: شاشة `/pr/statistics` ما زالت تنادي `/api/dashboard/pr/` على المونوليث —
> لأن تطبيق `dashboard` لم يُنقل بعد (انظر الفقرة التالية).

## ما زال داخل المونوليث

`dashboard/apis/views.py` يقرأ نموذج `Survey` مباشرةً لبناء لوحة تحليلات PR.
يجب لاحقاً إما نقل تلك الواجهة إلى هذه الخدمة، أو جعلها تستهلك `/api/pr/`.
