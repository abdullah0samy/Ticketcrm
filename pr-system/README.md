# ABC Hospital — PR System (standalone)

نظام **علاقات ورضا المرضى (Patient Relations)** بعد فصله بالكامل عن نظام التذاكر
(المونوليث Django + واجهته)، ليصبح مشروعاً قائماً بذاته: خلفية وواجهة ومنفذ ومسار خاص.

```
pr-system/
├── backend/    Django + DRF   → http://localhost:8001
└── frontend/   React (CRA)    → http://localhost:3002
```

> ⚠️ لا تخلط بينه وبين مجلد `abc-pr/` في الجذر — ذاك نظام PR **آخر** مكتوب من الصفر
> بـ Express + React، بينما هذا هو الموديول المستخرج من نظام البرودكشن الفعلي.

## التشغيل

```bash
# الخلفية
cd "E:/Ticket System/pr-system/backend"
./.venv/Scripts/python.exe manage.py runserver 0.0.0.0:8001 --noreload

# الواجهة
cd "E:/Ticket System/pr-system/frontend"
npm start                 # يقرأ .env.local -> PORT=3002
```

| الرابط | الوصف |
|--------|-------|
| http://localhost:3002 | الواجهة |
| http://localhost:8001/swagger/ | توثيق الـAPI |
| http://localhost:8001/admin/ | لوحة إدارة الخدمة |

**الدخول:** برقم البصمة `fingerid` — `3` (وكيل بقسم يملك وحدة PR) / `Admin@123`

## ماذا تغيّر عند الفصل

### الخلفية
- مشروع Django مستقل (`prcore`) بدل `ABCHospital`.
- يضم تطبيق `pr` كما هو (23 ترحيلاً محفوظة) + تطبيق `users` **للمصادقة فقط**
  (نفس الجداول، فتظل التوكنات الحالية صالحة).
- **صفر** استيراد من `ticket` أو `dashboard`.

### الواجهة
- شاشات `/pr/*` أصبحت في الجذر: `/` · `/create` · `/view` · `/view/:id` · `/statistics`
  (مع تحويلات من المسارات القديمة `/pr/*` حفاظاً على الروابط المحفوظة).
- **أُزيلت تبعية WebSocket** — كانت لنظام التذاكر، ولا تحتاجها شاشات PR.
- المتجر (Redux) يضم 3 شرائح فقط بدل 13.
- التبعيات 28 حزمة بدل 46.

## فروق أمنية مقصودة عن المونوليث

| # | الفرق | السبب |
|---|-------|-------|
| 1 | لا أسرار في الكود (كلها من البيئة) | المونوليث يضمّن `SECRET_KEY` وكلمة مرور القاعدة |
| 2 | `verify=True` على TLS | كان `verify=False` |
| 3 | Swagger محمي خارج التطوير | كان مكشوفاً بلا مصادقة |
| 4 | `AnonRateThrottle` = 60/دقيقة | كان 10,000,000/يوم |
| 5 | **إصلاح تسريب بيانات المرضى** | شرط الصلاحية كان مقلوباً فيسمح لأي مستخدم غير أدمن بالقراءة |

## المتبقي

`dashboard/apis/views.py` في المونوليث ما زال يقرأ نموذج `Survey` مباشرةً لبناء
تحليلات PR. الخطوة التالية: نقل تلك الواجهة إلى هذه الخدمة أو جعلها تستهلك `/api/pr/`.
